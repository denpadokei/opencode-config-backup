# note 記事執筆・エクスポートスキル

note.com 向けの記事を書き、note のインポート機能にそのまま食わせられるファイルを
出力するまでを一貫して行う。返答はユーザーとの対話に合わせて日本語で行うこと。

## 全体の流れ

1. **要件を確認**（わからない場合のみ）: 記事のテーマ、読者層、目安の長さ、トーン
2. **本文を執筆**: 下記「執筆ガイドライン」に従う。まずユーザーに本文を確認してもらう
3. **ファイルをエクスポート**: 下記「MT形式の仕様」に従って `.txt` を出力（WordPress
   からの転記など元データがある場合のみ WXR `.xml`）
4. **ユーザーが note にアップロード**: インポートされた記事は「記事一覧」に
   **下書き** 状態で入る（インポート完了は最大3日、メールで通知される）
5. **エディタで仕上げの確認**: 装飾・埋め込み・タグはインポートされない場合がある
   （下記チェックリスト）

## 執筆ガイドライン

- 言語: 日本語（ユーザーが明示的に指定した場合を除く）。ですます調が基本
- 段落は短め（2〜4文）。1文は60〜90字を目安に分割する
- 見出しは `<h2>` / `<h3>`。序論 → 手順や本論 → まとめ の順
- 手順記事は番号付きリストで「1手順1操作」。スクリーンショットが必要な箇所は
  `（ここにスクリーンショット）` とプレースホルダを置き、ユーザーが後で挿せるようにする
- 技術記事ではコードを `<pre><code>...</code></pre>` に置く。表示確認は
  インポート後のエディタで行う前提なので、複雑な装飾はしない
- ユーザーの好み: 決め打ちでまとめて書かず、1トピックずつ確認しながら進める

## MT形式の仕様（.txt / UTF-8）

note に認められるのは WordPress / LINE BLOG 系の MovableType エクスポート形式。
**`.txt` ファイル**、文字コード **UTF-8**、上限 **20MB / 1000記事 / ファイル**。

構造:

```
AUTHOR: 著者名
TITLE: 記事タイトル
STATUS: Publish
PRIMARY CATEGORY:
CATEGORY:
DATE: 08/12/2026 10:00:00
-----
BODY:
本文1行目
（画像は <img src="https://..." /> ）
-----
EXCERPT:
-----
KEYWORDS:
-----
--------
```

- **記事の区切りはハイフン8個 `--------`（半角）**。5個 `-----` はフィールド区切りと
  別の意味。**ファイルの最終行も必ず `--------` で終わること**（なければエラー）
- 必須フィールド: `TITLE:`、`BODY:`、`DATE:`。`DATE` は `MM/DD/YYYY hh:mm:ss`
  （月/日/年 時:分:秒）。無い記事があるとインポート失敗のメールが来る
- 複数記事を1ファイルに入れる場合は各記事を `--------` で区切る
- インポートされた記事は **常に下書き** になる（STATUS の値は問わない）

## 日時の挙動

- ファイル内の `DATE` が基本そのまま使われる
- `2014-04-07 12:00` より前の日付は `2014-04-07 12:00` に丸められる
- インポート実行日より未来の日付は、実行日時に丸められる
- 公開時に記事の公開日を選べるので、通常は当日の日時で出して問題ない

## 画像

- `<img src="https://...">` で、src が `http://` / `https://` で始まる
  **JPEG / PNG / GIF** のURLのみインポートされる（画像は note のサーバーに保存し直される）
- ローカルパス・data URI・WebP などは**手動で張り直し**になる
- 画像URLは自前でホストしたもの（リポジトリの raw URL など）を使うか、
  インポート後に note エディタで差し込む

## WXR形式（.xml）

WordPress からの転記など元データが WordPress エクスポートのときのみ使う。

- 文字コード UTF-8、上限は MT と同じ
- インポート対象は **WordPress上で公開済みの投稿のみ**（下書き・固定ページは対象外）
- ファイルを手で編集すると名前空間エラーで失敗しやすい。生成する場合は WordPress
  正規のエクスポート構造（rss / channel / item、dc / content / excerpt / wfw / wp の
  各名前空間）を崩さないこと
- 自分で1から XML を書くより **MT形式を推奨**

## インポートされないもの（要・手動確認）

- 埋め込み（iframe / 動画 / SNS埋め込み）— 文字列として入る
- 文字装飾・太字・色の一部
- タグ・ハッシュタグ・関連商品・有料設定・要約（サマリー）
- リンクカード

## エクスポート時のチェックリスト

1. 文字コードが UTF-8（BOMなし）か
2. 各記事に `TITLE:` `BODY:` `DATE:` があるか
3. フィールド区切り `-----`、記事区切り `--------` の個数（特に最終行）
4. 20MB・1000記事以内か（超えるなら分割。各ファイルが `--------` で終わること）
5. 画像URLがすべて `http(s)` か

## アップロード後のチェックリスト（ユーザーに伝える）

1. 記事一覧に下書きが入っているか（完了メールが来るまで最大3日）
2. エディタで開き、見出し・太字・埋め込み・画像が正しいか確認して再設定
3. タグ・要約・公開日時を設定して公開
4. プレビューで全文チェック（特にコードブロックの崩れ）
